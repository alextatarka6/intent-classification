# Data

Everything in this directory is generated by `src/prepare_data.py` (run via `./run_all.sh`).
Seeds, k values and sources are defined once in `src/config.py`. Rerunning reproduces every
file byte for byte.

Dataset: **Banking77** (`PolyAI/banking77` on Hugging Face, CC BY 4.0): 77 intents,
10,003 train / 3,080 test. No other data is used.

## How the raw data is obtained

The `PolyAI/banking77` Hub repo contains only a loading script (`banking77.py`), which
`datasets` >= 4 no longer runs. The pipeline therefore replicates the script directly:

- Label names and their integer ids (0–76) come from the Hub repo's `dataset_infos.json` at
  commit `90d4e2ee5521c04fc1488f065b8b083658768c57`. The ids match `load_dataset("PolyAI/banking77")`.
- The text comes from the two CSVs that the script downloads
  (`PolyAI-LDN/task-specific-datasets/banking_data/{train,test}.csv`). They are pinned to GitHub
  commit `9d081458ff52e53cf7e848f414e6e9344e4e6696` and parsed with the script's exact
  `csv.reader` settings. The row counts are checked against 10,003 / 3,080.

## Files

All CSVs have the columns `text, label, label_name`, where `label` is the HF integer id.

| Path | Contents |
|---|---|
| `raw/source/{train,test}.csv` | Untouched source CSVs as downloaded. |
| `raw/source/checksums.json` | Source URL and sha256 of each source CSV. |
| `raw/{train,test}.csv` | Full train / test splits, with the integer label added. |
| `raw/label_names.json` | The 77 intent names, indexed by label id. |
| `new_intents.json` | The 7 held-out "new" intents and the seed used to pick them. **Frozen**: the script reads this file if it exists and never regenerates it. |
| `splits/standard/seed{s}_k{k}.csv` | Standard k-shot training set: k examples for each of the 77 intents. |
| `splits/new_intent/seed{s}_k{k}.csv` | New-intent training set: **all** training rows of the 70 old intents, plus k examples for each of the 7 new intents. |
| `splits/test/test_all.csv` | The full test set (3,080 rows), unchanged. |
| `splits/test/test_old.csv` | Test rows whose intent is one of the 70 old intents (2,800 rows). |
| `splits/test/test_new.csv` | Test rows whose intent is one of the 7 new intents (280 rows). |
| `splits/manifest.json` | Every split file with its seed, k and row counts, plus every (seed, k, intent) that was capped. |

Here `s` ∈ `SEEDS = [0, 1, 2, 3, 4]` and `k` ∈ `KS = [1, 5, 10, 20, 50]`, which gives
25 standard files and 25 new-intent files.

## How the splits are sampled

- **New intents.** 7 of the 77 intent names are drawn once with
  `numpy.random.default_rng(NEW_INTENT_SEED=2025)`, without replacement, and written to
  `new_intents.json`.
- **k-shot sampling.** For each seed, `default_rng(seed)` draws one random permutation of each
  intent's training rows, with intents visited in label-id order. The k-shot sample is the first k
  rows of that permutation. As a result:
  - The samples are **nested**: for a given seed, the k=5 sample is a subset of the k=10 sample,
    and so on.
  - Sampling is without replacement, so no row repeats within a split.
  - The new-intent split for (seed, k) uses **the same** new-intent examples as the standard
    split for (seed, k).
- **Capping.** If an intent has fewer than k training rows, all of its rows are used, a warning is
  printed, and the case is logged in `manifest.json`. This only happens at k=50, for
  `contactless_not_working` (35 rows) and `virtual_card_not_working` (41 rows, which is also a new
  intent). At k=50 the standard split has 3,826 rows instead of 3,850, and the new-intent split
  has 341 new-intent rows instead of 350.
- **The test set is never modified.** The test subsets only filter its rows by intent.
